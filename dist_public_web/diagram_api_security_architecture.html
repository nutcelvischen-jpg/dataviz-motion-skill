API 金鑰資安防護與前後端分層架構

新手開發 AI 應用最致命的直覺錯誤：「直接在前端 HTML / JS 中寫死 API Key」。 只要造訪者按一下滑鼠右鍵「檢視網頁原始碼」或按 F12，金鑰在 30 秒內就會被爬蟲抓走。本圖解以編輯級架構對比，示範如何透過 BFF（Backend-for-Frontend）後端代理 實現零信任資安隔離。

韓國開發者遭 Claude API 扣款 1,660 萬美元（約 5.3 億台幣）： 開發者因程式碼缺乏預算熔斷機制、金鑰未於安全後端隔離，且遭外部併發循環觸發，短時間內累積上千億 Token 帳單。

🚨 守則一：前端代碼視為「公共廣場」

任何在瀏覽器執行的代碼（HTML, JS, CSS, Webpack 打包檔），只要造訪者按一下右鍵「檢視原始碼」或 F12，其內部的字串完全公開透明。 任何寫在前端的 API Key 都等於直接貼在公車站牌上。

🛡️ 守則二：金鑰必須放在「伺服器金庫」

API Key 必須存放在只有伺服器能讀取的環境變數（.env 或 Cloud Secret Manager）， 且 .env 必須加入 .gitignore，絕對不可推送至 GitHub！

💸 守則三：必須設定「每日花費熔斷」

在 OpenAI / Anthropic 儀表板中，務必設定 Monthly Budget Limit（預算硬性上限） 與 Usage Alerts。 即使不幸外洩，最多扣完預設額度（例如 \$20 美元）即刻斷線，絕不會引發 1,660 萬美元的滅頂災難。
