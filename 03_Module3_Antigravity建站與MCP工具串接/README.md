## 二、 什麼是 MCP（Model Context Protocol）？

過去每個 AI 工具要讀取你的 Google 日曆、GitHub 或本地 Excel，都需要各自寫一套封閉的 Plugin 或 API 介面；
**MCP（模型上下文協議）** 就像是 **AI 世界的 Type-C 連接埠**：
- **標準化介面**：由伺服端（MCP Server，如 Google Workspace、Filesystem、Chrome DevTools）與客戶端（MCP Client，如 Claude Desktop、Antigravity）組成。
- **動態工具發現**：當 AI 需要特定能力時，自動發現並載入工具清單（Eager vs. Lazy Loading）。
- **權限控制明確**：每一次涉及硬碟寫入或外部服務呼叫，都可設置使用者確認關卡。

```text
┌─────────────────┐       MCP Protocol        ┌───────────────────────┐
│                 │ ◄───────────────────────► │  MCP Server (本地檔案) │
│  Antigravity /  │                           ├───────────────────────┤
│  Claude Desktop │ ◄───────────────────────► │  MCP Server (Google)  │
│  (MCP Client)   │                           ├───────────────────────┤
│                 │ ◄───────────────────────► │  MCP Server (GitHub)  │
└─────────────────┘                           └───────────────────────┘
```

## 三、 大專院校與機關資安三鐵律

在將 AI 接入內部工作流程時，必須嚴守三大原則：
1. **資料去識別化（脫敏原則）**：學生身分證字號、學號、手機號碼、同仁考績與非公開財務報表，在上傳或傳遞給外部雲端模型前，必須透過腳本或正則表達式進行模糊化（Masking）。
2. **API 金鑰與憑證不落地公開**：嚴禁將 API Key 直接寫死在公開前端 HTML/JS 程式碼中，應使用環境變數（`.env`）或受保護的後端代理。
3. **最小權限原則（Least Privilege）**：設定 MCP 伺服器時，若只需「讀取」資料夾，絕不給予「寫入」或「刪除」權限。
