Agent Loop（行動循環）是選擇下一步、執行、觀察結果，再決定是否修正或完成。涉及需要人確認的動作，應先暫停等待；Agent、Skill、MCP 是不同角色，並非每個產品都必經的升級階梯。

名稱角色
Agent圍繞目標選擇行動並檢查結果的系統。
Skill可重用的方法與指引。
MCP連接工具與資源的協定。

Workflow 和 Agent，差在誰決定下一步

同樣是整理報名表，有時照流程做就夠，有時需要根據結果調整。

  • Workflow：先把路徑安排好

    程式事先寫好順序和條件分支。即使其中用了模型，接下來走哪條路仍由預定規則安排。

    讀取名單 → 依規則清理 → 統計 → 製圖

  • 單次工具呼叫：請工具幫忙做一件事

    模型提出「計算各場次人數」的請求，程式檢查後執行，再把結果交回。一次呼叫不代表已經建立完整的 Agent 系統。

    提出計算請求 → 程式執行 → 回傳結果

  • Agent：依結果決定下一步

    模型在系統允許的範圍內選擇行動。例如發現場次欄位缺漏，就先查資料或詢問，再繼續統計。

    選擇行動 → 工具執行 → 觀察結果 → 再選下一步

兩種安排可以混合使用。任務步驟固定時，清楚的 Workflow 往往就夠；需要依結果調整時，再考慮加入 Agent。

什麼時候該停下來？

Loop 不是一直重試。開始前就要約定完成條件，以及遇到哪些情況必須停下。

  • 已經完成：產物通過檢查，就交付結果。
  • 缺資料或權限：說明缺少什麼，請使用者補充或確認。
  • 重複失敗：達到設定的重試或步數限制，就回報卡在哪裡。
  • 資源到上限：達到時間或費用限制，就結束這次執行。

這些限制由應用程式或 Harness 管理。看 Token 與費用的關係 →

想一想：一定需要多個 Agent 嗎？

先用一個 Agent 或固定流程測試。分工會增加交接、資訊傳遞與結果核對的工作；有明確需要時，再引入多個角色。看 Multi-agent 與 Handoff。
