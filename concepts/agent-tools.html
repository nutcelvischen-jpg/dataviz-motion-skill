Agent
智慧代理人
圍繞目標選擇行動、使用工具並依結果調整的系統。例：決定先讀取名單，再計算人數並製圖。
Agent Loop
行動循環
選擇下一步、執行、觀察結果，必要時修正或停止。例：計算結果與筆數不符時，回頭檢查資料。
Tool Calling
工具呼叫
模型提出結構化的工具請求，由應用程式執行並回傳結果。例：呼叫程式計算每個組別的人數。
Agent Harness
執行框架
安排模型、工具與回饋如何協作的程式和規則；可包含權限、步數限制與檢查。例：只開放讀取指定資料夾，限制重試次數。
Skill
可重用的工作指引
供支援的系統載入的一組指引或資源，讓工作方法可以重複使用。例：一份「檢查報名資料」的步驟與檢核準則。
MCP
模型上下文協定
讓 AI 應用以共同方式連接工具和資料的協定；是否能使用仍取決於設定與權限。例：透過 MCP 連接已授權的資料來源。
RAG
檢索增強生成
先從外部資料找出相關內容，再把內容提供給模型回答；來源仍需核對。例：先查詢活動簡章，再依簡章回答報名規定。
Context Engineering
上下文工程
整理本次模型呼叫需要的指引、對話、資料與工具資訊。例：只帶入相關欄位、資料說明與本次任務。
Human-in-the-Loop
人工參與與確認
在需要判斷或授權的節點，讓人檢查、修正或決定是否繼續。例：寄出名單或對外發布報告前先確認。
Multi-Agent／Handoff
多代理人與交接
把工作分給不同代理人，並傳遞任務與結果；仍需清楚界定責任與權限。例：資料整理完成後，交給另一個代理人檢查圖表。

參考：Anthropic：Building effective agents、MCP 官方文件。

Schema：工具請求要怎麼填？

可以把 Schema 想成工具的填寫表格：要提供哪些欄位、每個欄位接受什麼格式、哪些值才有效。

例如「統計報名人數」工具可能要求填入場次欄位，以及要排除的報名狀態。模型提出的內容仍要由程式檢查，不能因為格式看起來正確，就認定操作合理。

  1. 工具說明有哪些操作可以用？
  2. 模型填參數提出結構化請求
  3. 程式驗證格式、範圍與權限
  4. 工具執行回傳結果或錯誤

Tool 是系統提供的一項操作；API 是程式之間對接的介面。有些工具透過 API 連接外部服務，也有工具直接在本機計算。MCP 則提供共同的連接方式，能和 API、Tool Calling 一起使用。

有工具，不代表每個動作都能做

「可以讀報名表」不等於「可以把名單寄出去」。應用程式需要在執行前，檢查資料範圍、操作權限，以及這次是否已取得必要確認。

需要人判斷或授權時，交由 Human-in-the-Loop 處理；允許哪些工具、何時停止，則由 Harness 等執行配套管理。
