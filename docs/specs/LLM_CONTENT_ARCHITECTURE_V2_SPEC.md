## 3. 共用閱讀與版面規則

### 3.1 一頁一個主要任務

每個專題或概念章節的開頭固定回答：

1. 這頁解決什麼問題：短問題式標題。
2. 讀完能說明什麼：一至兩項具體學習成果。
3. 需要先懂什麼：最多兩個概念連結；沒有必要就不顯示。
4. 本頁會經過哪些步驟：三至五個簡短段落錨點。

不要在首屏放大段研究摘要、供應商介紹或英文術語列表。

### 3.2 閱讀模板

一般概念章節按以下順序編排：

    核心問題
    一句話理解
    主圖與圖說
    同一個具體例子
    常見誤解與適用限制
    一句結論
    下一步／進階細節

不是每一項都要做成卡片。一般段落用標題、留白與分隔線；只有操作區、對照區或需要區別的補充區使用容器。

原理與必要例子預設可見。完整表格、原始程式碼、技術推導、長篇補充可以收合；不把所有正文藏進手風琴。

### 3.3 版面尺寸與閱讀節奏

以下數值是起始設計約束，允許為實際中文字寬微調，但必須通過後述視覺驗收。

| 項目 | 桌機 | 手機 |
|---|---|---|
| 頁面外框 | 最大約 1200px，左右留白至少 24px | 左右留白 16～20px |
| 章節目錄 | 左側約 200～220px，與正文間隔 32～48px | 收合為「本頁目錄」，顯示目前章節 |
| 一般正文 | 約 680～760px 寬 | 佔可用寬度 |
| 正文字級 | 17～18px，行高約 1.8～1.95 | 16～17px，行高約 1.8 |
| 頁面標題 | 約 36～44px，不堆放長副標 | 約 28～32px |
| 區塊間距 | 約 40～56px | 約 28～40px |
| 主圖／比較表 | 可適度超出正文寬，但仍在外框內 | 使用單欄或特定表格捲動區 |

- 約 960px 以下收起側欄，避免正文被擠成窄縫。
- 不增加第三個永久側欄。
- 頁面標題以中文問題為主；英文和分類標籤使用次要層級。
- 首屏應看得到本頁問題、短結論，以及第一個內容或操作的起點。
- 正文不使用滿版超長行；大表格可以比正文寬。
- 移除圖鑑底部目前遮住內容的浮動入口膠囊列，以共用導覽取代。
- 不用「每段一個大色塊」「每個名詞一張同樣大的卡片」維持整頁同一節奏。
- 保留目前色系；強調色用在目前位置、主要動作和結果差異。
- 主要操作區不使用進場淡入來延遲可讀性。

### 3.4 圖解的語意規則

- 只有真實的先後／資料流／因果關係才使用箭頭。
- 時序用步驟或泳道；同時存在的選項用對照；分類使用群組。
- 每張主圖只回答一個問題，主要節點以三至六個為原則。
- 箭頭需寫出傳送內容或動作，例如「附上先前對話」，不能只有箭頭。
- 圖下放一段可獨立閱讀的文字說明。
- 重點改變以文字標示，不只使用紅綠色。
- 複雜總覽圖可以保留為進階展開內容，但不能成為唯一的初學者說明。
- 手機需有等價的垂直步驟；不能單純把整張工程圖縮小到文字不可讀。

## 4. encyclopedia.html：真正重排核心內容

### 4.1 整頁順序

1. 共用導覽。
2. 標題「大語言模型概念圖鑑」。
3. 說明「按問題查閱原理、使用方法與工作流程；第一次接觸可先走六站學習路線。」
4. 四分區索引與「從六站開始」次要連結。
5. 左側分組目錄、右側正文。
6. A 基本原理。
7. B 可靠使用。
8. C 選擇與工作流程。
9. D 專題選讀索引。
10. 頁尾。

索引不能再接回完全未整理的原長頁。下面列出的遷移與縮編都是必做。

### 4.2 A 基本原理：章節順序與範圍

| 順序 | 章節／ID | 要呈現什麼 | 要移走什麼 |
|---|---|---|---|
| A1 | 文字如何變成回答／glossary | 一句話、生成循環、同一段輸入的例子 | 品牌排名、費率、工程安全 |
| A2 | 文字如何切成 Token／token-visualizer-card | 定義、示意切分、字元比較、切分限制 | 百萬次費用指標移到成本節 |
| A2 補充 | 數字母為什麼值得驗算／strawberry | 一個短例子、可驗算方法、適用限制 | 冗長雙軌解說可收合；不宣稱所有模型必然數錯 |
| A3 | 前文怎麼被帶入這次回答／context | 保存、選取、組裝輸入、容量限制 | 完整工程時序圖連至 memory.html |
| A4 | 同一題為什麼可能有不同回答／sampling | 候選、選取與差異，簡單示意 | 公式與參數深論收合或移入選讀 |

不要把 API Key 放在 Token 與上下文中間。向量與微調移至專題，核心只保留必要的一句解釋和連結。

分詞區沿用可編輯輸入、中英文／程式預設、數量和色塊。若仍使用 simulateBpeTokens 等簡化方法，必須顯示「示意切分」與「示意 Token 數」，不能稱為正式 BPE 或供應商計費結果。

### 4.3 B 可靠使用：從問題走到方法

新增總區 ID reliable-use，下列子章均有獨立錨點：

| ID | 標題方向 | 主圖／主例子 | 對應實驗 |
|---|---|---|---|
| evidence-check | 流暢回答可以直接當證據嗎？ | 來源不足的回答 → 取得資料 → 核對 | probability |
| tool-verification | 哪些工作需要交給工具？ | 資料 → 計算 → 核對 → 解釋 | arithmetic |
| instruction-boundaries | 文件中的指令可以直接照做嗎？ | 原任務、外部內容與工具行動的界線 | injection |
| key-permissions | 金鑰與工具權限由誰管理？ | 使用者 → 應用服務 → 模型／工具 | security |

優先使用現有六站與實驗中的通用說明重組，避免再寫一份長篇百科。每節主要解說以短文、一個圖和一個例子為主；完整案例與工程細節連至專題。

模型本體、聊天應用、外部工具在圖和文字裡分開命名。例如「應用程式附上前文」不能寫成「模型永久記住」。

### 4.4 C 選擇與工作流程

按以下順序排列：

#### C1 成本：pricing 與 api-trial

- 先說「哪些用量會影響費用」，再讓讀者調整數字。
- 主試算區顯示輸入、輸出、單價假設和總額，計算依據始終可見。
- 教學模式可沿用六站的假設單價，但要明確顯示「教學假設，非供應商報價」。
- 既有官方／OpenRouter 費率切換及表格保留在「查閱費率資料」區；資料狀態依第 12 節處理。
- 保留既有快速用量選擇。所有摘要指標與表格必須讀取同一個目前用量值，避免上方顯示 2,000、下方卻依另一個分詞值計算。
- 若某表只估輸入費用，名稱必須寫「輸入費用」，不能寫成總成本。
- api-trial 保留為「進階：檢視一次 API 用量」收合區；直達該錨點時自動展開。
- 預設教學模擬；選模型、輸入金鑰或真實請求都不是閱讀本節的必要條件。

#### C2 模型比較：models

先提供三個選擇問題：「工作需要什麼能力？」「資料可以放在哪裡？」「使用條件與成本是什麼？」

接著呈現一張精簡比較表，欄位固定為：

    名稱｜取得／部署方式｜用途說明｜使用條件｜資料狀態／來源

- 預設摘要表讓讀者能橫向比較，完整模型介紹改為每筆「查看細節」。
- 保留全部既有模型可達性及篩選能力；不直接刪掉不想展示的資料。
- 篩選使用中性分類，如「雲端服務」「開放權重」「本機部署」；同一項目可以屬多類。
- 不以國別、宣傳形容詞或未核實排名作為初學者第一個選擇依據。
- 模型能力、硬體門檻和價格使用各自明確欄位，避免單張卡片混成一段長文。
- 不複製另一套價格常數。表格、摘要、細節讀取同一份資料。
- 不聲稱替使用者找出「最佳模型」，只呈現可比較的條件。

#### C3 雲端與本機：cloud-vs-local

- 先用同一個任務比較「資料送往哪裡、在哪裡運算、誰負責維護」。
- 桌機兩欄對照；手機依同一欄位順序呈現兩個方案。
- 圖下列出應考量的條件；硬體矩陣放進進階區。
- 不把「沒有按 Token 收費」直接顯示為「完全免費」；成本欄清楚列出本頁計算包含與未包含的項目。
- 不把部署地點直接等同於隱私或合規保證。

#### C4 工作流程：agent-evolution

- 保留此舊 ID，但主標題改為「從一次問答到完成工作」。
- 先展示一個完整任務：「整理報名資料並製作人數圖」。
- 流程包含目標、下一步、工具、觀察、核對、交付；未達標回到下一步，需要人確認則暫停。
- Agent、Skill、MCP 用角色比較表說明，不畫成所有產品必經的升級階梯。
- 執行時長與限制可以短表呈現；時長分類需標明是教學分類或原資料的統計口徑。
- 四大商業產品矩陣、品牌故事、長篇產業研究與重大事件搬至下列專題。

### 5.3 記憶實驗的完整樣板

固定教學例子，三個頁面共用：

    先前訊息：我叫大華，我的貓叫皮皮。
    新問題：我的貓叫什麼？

畫面順序：

1. 標題：「模型這次真的收到貓的名字嗎？」
2. 目標：「分辨聊天畫面保存的資訊，與本次實際提供的輸入。」
3. 預測：「如果本次只送出新問題，資訊足夠嗎？」選項為「足夠／不足／不確定」。
4. 按鈕：「比較兩種輸入」。

- 預設教學流程完全不需要金鑰，八個實驗皆可完成核心觀察。
- 真實 API 自由測試保留在「進階：使用自己的模型」區，不放在頁面最醒目處。
- 保留現有供應商選項、模型選擇及既有設定相容性，不新增供應商或登入流程。
- 帶有效 lesson 參數進入時，沿用第一輪規則：本次使用教學模擬，不覆寫獨立實驗室的供應商偏好。

- 本輪不需要真的付費呼叫 API 驗收；以模擬回應驗證狀態及錯誤流程即可。
