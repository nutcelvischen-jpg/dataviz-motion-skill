## 第一個樣板的具體範圍

建議先改 Agent 任務流程，仍使用「報名表變成人數圖」的既有例子。

1. 準備 Context。
2. LLM 提出下一步。
3. 程式檢查：格式、權限與必要確認是否通過？
4. 工具執行，回傳結果。
5. 更新 Context 並核對結果。
6. 完成條件是否達成？
7. 達成：交付結果。
8. 無法繼續：暫停並詢問。

主圖控制在八個節點；判斷 3 的「未通過」連到暫停，判斷 6 的「未完成且仍可繼續」返回模型，超限或反覆失敗則連到暫停。長說明、RAG／Memory 的選用與額外名詞仍放在既有深入區。這是工具任務的示例，沿用原有提醒：不是每一輪都需要工具。

## 套用時的界線

- 沿用 `DESIGN.md` 的米白、深墨、鏽紅、橄欖綠與現有中文字體；既有專案設計是視覺依據。
- 原生 HTML 名詞連結、鍵盤操作、返回原分支、深連結、實驗與進度功能繼續保留。手機採可讀的直向流程，避免把桌面圖整張縮小。
- 形狀、位置與文字共同表達意思；單靠顏色無法區分「判斷」或「未啟用」。線條只保留具有意思的關係。
- Skill 的自含 HTML/SVG 輸出適合另外保存示範稿；整合進既有網站時，以原有功能和已確認的設計為準，不整頁換成它的預設模板。
- 目前 skill 的共用 style-guide 仍是預設值，專案沒有 `.diagram-design` marker。本輪只做現況分析，因此沒有觸發新圖生成，也沒有修改共用樣式。若後續產圖，應從本專案的既有設計建立有效樣式；使用者已確認的網站配色與中文字體無須重選。
- Image Gen 的資料櫃／桌面插圖負責生活比喻；Diagram Design 的圖解負責精確的關係、分支與流程。兩種素材可以在同一教材中接續使用。
