# 🛠️ Skill 工程化設計心法與撰寫指南

## 一、 Skill 檔案結構規範（以 Antigravity / Claude 規範為例）

一個可供系統調用或重複使用的 Skill 檔案（通常命名為 `SKILL.md`），通常包含兩大區塊：
1. **YAML Frontmatter（元資料頭部）**：讓系統或目錄識別該 Skill 的名稱、簡介與觸發條件。
2. **Markdown 系統提示詞本體**：詳細的執行規則與操作範例。

```markdown
---
name: skill-name-identifier
description: 一句話清楚描述這個 Skill 解決什麼問題，以及什麼時候該使用它。
---

# 技能名稱（Title）

## 1. 角色設定與基本原則 (Role & Core Values)
...

## 2. 邊界約束與負向提示 (Constraints & Boundaries)
...

## 3. 標準作業流程 (Step-by-Step SOP)
...

## 4. 輸出格式規格 (Output Schema)
...

## 5. 少樣本示範 (Few-Shot Examples)
...
```

## 二、 負向提示（Negative Constraints）實戰技巧

很多時候，讓 AI 表現出色的關鍵不在於告訴它「要寫什麼」，而在於明確禁止它「不能寫什麼」：

### ❌ 常見失敗的空泛提示：
> 「請寫得專業一點，不要太死板。」（模型無法量化何謂「死板」）

### ✅ 精準有效的負向約束：
```text
【嚴格禁止事項】：
1. 嚴禁使用「至關重要」、「不容小覷」、「劃時代」、「引領未來」等空泛讚美詞。
2. 嚴禁擅自補充原文未提及的數據、人名、機構或法規條號。
3. 若原文資訊不足，請明確標示「【待確認】」，不得自行猜測補充。
4. 嚴禁變更公文原文中的預算金額與截止日期。
```

## 三、 少樣本提示（Few-Shot Prompting）的力量

給 AI 一個具體的「輸入前 $\rightarrow$ 修改後」對照示範，其效果勝過寫十條規則：

```markdown
### 範例對照 (Example)：
**【輸入原文】**：
這次我們系上想要辦一個 AI 的講座，大概花十萬塊，希望學校可以補助，因為現在 AI 很重要，大家都應該要學。

**【優化輸出】**：
主旨：函陳本系擬辦理「AI 驅動商業創新應用實務講座」經費補助案，計新臺幣 100,000 元整，簽請 核示。
說明：
一、依據教育部推動大專校院智慧科技人才培育計畫辦理。
二、為強化本系師生之生成式 AI 應用能力與產業務實接軌，特規劃旨揭講座。
三、檢附活動企劃書及經費預算表各乙份。
擬辦：奉核後，依校內相關規定辦理各項招募與核銷程序。
```
