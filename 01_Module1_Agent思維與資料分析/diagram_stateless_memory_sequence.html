Sequence Diagram · Semantic Pattern: Stateless Request-Response

大語言模型無記憶本質：對話歷史打包重送時序圖

模型本身是完全無狀態的靜態函數 \( y = f(x) \)。前端看似具有「長期記憶」的連貫對話，實際上是客戶端在背後將所有歷史對話打包成巨大陣列重複遞交，這導致 Token 消耗呈二次方 \( O(N^2) \) 暴增與上下文稀釋。

01 / ARCHITECTURE
API 本質是無狀態白紙
大語言模型伺服器內部沒有用戶的 Session 記憶庫。每次 API 調用都是一次獨立的冷啟動矩陣計算，對話歷史由客戶端全額承擔。
02 / COST & COMPLEXITY
成本 O(N²) 二次方暴增
第 1 輪傳送 1 句話，第 10 輪傳送前 10 句話。隨對話拉長，API 帳單指數級飆升，且早期指令逐漸被淹沒（Lost in the Middle）。
03 / AGENT TAKEAWAY
漸進式載入（Progressive）
在 Module 2 製作自訂 Skill 與 Agent 時，切忌將整本厚重的 SOP 塞在對話開頭，必須透過動態卡匣在精準節點按需加載。
