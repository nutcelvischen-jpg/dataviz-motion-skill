Architecture Delta · Semantic Pattern: Compensating Security Layers

提示詞注入攻防對比：單一流混淆 vs. 三層邊界防禦流水線

以臺北捷運 AI 客服遭民眾測試歪樓寫代碼為鑑：LLM 天生無硬體指令隔離，若僅寄託模型自我把關，攻擊者能輕易以偽裝情境覆蓋系統。唯有建立「前後端三層補償防衛流水線」，才能徹底收斂破防風險。

01 / ROOT CAUSE
單一輸入流天然混淆
LLM 只有單一 Input Stream，系統指令與使用者輸入混在一起計算機率，口頭約束無法抵禦情境偽裝與覆蓋攻擊。
02 / COMPENSATING LAYERS
三層外圍補償防線
依據 L1 離題過濾 ➔ L2 標籤邊界 ➔ L3 輸出清洗，由伺服器後端程式碼落實硬性驗證，絕不寄託於 LLM 的道德自律。
03 / MODULE 2 TAKEAWAY
Agent 工具呼叫安全邊界
在建構自訂 Skill 與 Agent 時，所有涉及資料庫寫入、檔案刪除與外部 API 呼叫，必須在 Tool 內部進行參數驗證。
