Token 是什麼？互動式分詞與成本試算沙盒

電腦只認得二進制數字，無法直接理解人類文字。LLM 透過 Byte-Pair Encoding (BPE) 演算法將文字切分成「詞元（Token）」。英文字詞通常 1 個單字切成 1~2 個 Token；繁體中文因多字元編碼，每個字約消耗 1.2~2.0 個 Token！

🍓 經典字母計數陷阱視覺解密 · THE STRAWBERRY PARADOX

為什麼大語言模型連小學生都會的「數字母」都數錯？

你問早期 ChatGPT：「strawberry 裡面有幾個 r？」它會自信地回答「2 個」。這絕非 AI 智商低，而是分詞壓縮帶來的「感官盲區（Sensory Blindness）」！請跟隨下方雙軌流程圖，看清人類眼睛與神經網路的認知鴻溝：

👁️ 人類認知路徑 · 字元級光學掃描 (100% 確定) 零認知盲區
01
視網膜光學感應與字元分離
人類肉眼一眼望去，單字被拆解為 10 個清晰分離的英文字母實體：
s t r#1 a w b e r#2 r#3 y
02
大腦指針循序點名比對 (Pointer Scan)
視線由左至右移動：第 3 位是 'r'，第 8 位是 'r'，第 9 位是 'r'。
03
確定性算術相加
大腦將 3 次命中做累加：1 + 1 + 1 = 3。
🎯 人類結論：精確命中 3 個 'r' (毫無負擔)
🤖 LLM 運算路徑 · BPE 分詞黑盒子 (結構性盲區) 字母實體完全消失
01
BPE 切詞機查字典切塊 (Tokenize)
Tokenizer 追求高壓縮率，將單字直接切成 2 塊語義積木：
Token #1: "straw" ID: 11245 + Token #2: "berry" ID: 32884
02
神經網路高維向量化 (Embedding)
Token 被轉換為 4096 維數學浮點數向量。英文字母完全被封閉在語義箱子裡，模型內部根本看不見字母拼寫！
straw ➔ [ 0.34, -0.81, 0.45, ... ] (稻草/吸管概念)
berry ➔ [ -0.14, 0.77, 0.62, ... ] (莓果概念)
03
注意力偏誤與機率猜測 (Blind Guessing)
模型沒有顯微鏡拆箱看字母！在語料中 "berry" 經常與 "double-r" (如 blueberry) 高度共現，注意力強烈指向「2」，脫口而出「有 2 個」，直接把前面 "straw" 的第 1 個 r 給忘了！
⚠️ 傳統 LLM 結論：頻繁猜錯為「2 個 'r'」
🛠️ 工程實務：徹底破解 Strawberry 陷阱的三大招式
招式 1

提示詞物理拆字 (Token Splitting)

指示 Prompt：「請把 strawberry 每個字母用空格分開：s t r a w b e r r y 再數」。強制 Tokenizer 將每個字母切成 1 個 Token，模型重獲視力！

招式 2

工具調用與 Python 執行 (Tool Calling)

讓 AI 撰寫代碼執行："strawberry".count("r") ➔ 3。以確定性程式消除機率幻覺，此為 Module 1 數據分析核心理念！

CORE FOUNDATIONS · 02

大語言模型必懂 6 大專有名詞視覺圖解

在進入 Module 1 的資料分析與 Module 2 的自訂 Skill 之前，這些核心詞彙是工程師與 AI 溝通的共同語言：

01 / QUANTUM OF LLM
Token（詞元）與 Tokenize
LLM 處理資訊的最小單位。英文通常由詞根、詞綴組成（如 un-believable 切為 2 個），中文常見 1 字對應 1~2 個 Token。Token 數量直接決定 API 帳單與運算延遲。
1 Word ≈ 1.3 Tokens ｜ 1 中文字 ≈ 1.5 Tokens
02 / BILLING & AUTH
API Key（金鑰憑證）
你在雲端模型供應商（OpenAI、Anthropic、Google）處的數位身分證與信用卡扣款憑證。具備極高資安敏感性，一旦直接寫死在前端 HTML/JS，會被爬蟲一秒盜刷成千上萬美元！
Headers: {"Authorization": "Bearer sk-..."}
03 / MEMORY CAPACITY
Context Window（上下文視窗）
模型單次對話能夠同時「閱讀」與「輸出」的最大 Token 上限。從早期 GPT-3.5 的 4K，進化到 GPT-4o 的 128K，再到 Gemini 1.5/2.5 Pro 的 2,000,000 Tokens（可直接吃下幾十本書或幾小時影片）！
Window = Prompt Tokens + Output Tokens
04 / CREATIVITY TUNING
Temperature & Top-P（採樣溫度）
控制模型輸出時的隨機性。Temperature 越低（如 0.0），模型只挑選機率最高的字，回答嚴謹、確定、適合資料分析與算術；越高（如 0.8~1.0），模型會隨機選取邊緣詞彙，適合創意寫作。
P(w) = softmax(z_i / Temperature)
05 / GEOMETRIC SEMANTICS
Embeddings（向量嵌入空間）
將文字轉換成數千個維度的浮點數向量（如 1536 維）。在幾何空間中，「國王」與「女王」的向量方向平行於「男人」與「女人」。RAG（檢索增強生成）正是利用餘弦相似度在向量空間找相關文檔。
Similarity = cos(θ) = (A · B) / (||A|| ||B||)
06 / CONTROL LAYER
System Prompt（系統提示詞）
在對話最一開始由開發者注入的最高指導方針，規範模型的角色、語氣、輸出格式與邊界。但如同我們在北捷案例所見：System Prompt 不是物理防火牆，仍會被惡意 Prompt Injection 繞過！
role: "system", content: "You are an expert analyst..."

ARCHITECTURE TRADEOFFS · 04

地端模型 (Local / Ollama) vs. 雲端模型 (Cloud API) 架構圖解

身為資料分析師或架構師，什麼時候該呼叫 OpenAI / Claude 雲端 API？什麼時候該在筆電或內網私有化部署 Ollama？關鍵在於權衡五大維度：

決策維度 ☁️ 雲端 API 模式 (OpenAI, Gemini, Claude) 🏠 地端自建模式 (Ollama, vLLM, 私有伺服器)
🔒 數據隱私與合規 資料需傳送至外部伺服器
雖然商業 API 承諾不使用客戶資料訓練，但在高度管制的金融、醫療、國防領域，外部傳輸本身即可能違反法規。 		100% 物理留存本地，零資料出境
網路線拔掉依然能流暢運行！完全符合最高等級 GDPR、醫療 HIPAA 或內部機密隔離規定。
💰 成本結構與收費 按量計費（Pay-as-you-go）
前期投入為 0；但如果業務流量極大（如每秒數百次呼叫），累積的 Token 帳單將非常可觀。 		前期硬體固定資產投入
日常呼叫 Token 邊際成本為 0！但需要投資高階 GPU（如 RTX 4090、A100 或 Mac M3/M4 Max 高統一記憶體）。
🧠 智能天花板與推理力 極致頂級（Frontier Intelligence）
背後是數千億甚至上兆參數的龐大叢集（如 GPT-4o, Claude 3.5 Sonnet），在複雜邏輯、跨領域推理遙遙領先。 		受限於本機顯存（VRAM）
個人筆電通常只能跑 7B~14B 模型，70B 需高階顯卡。在嚴密邏輯或細膩文筆上與雲端旗艦有明顯落差。
⚡ 部署與維運難度 零維運（Serverless）
申請 API Key，一行 requests.post 或官方 SDK 即可呼叫，全世界高可用性由巨頭維護。 		需要掌握基礎運維知識
需安裝 Ollama、配置 CUDA 驅動、處理量化格式（GGUF）、記憶體溢出（OOM）與高並發排隊問題。
