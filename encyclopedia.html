模型與資料

  • LLMLarge Language Model，大型語言模型；依上下文產生文字。↗
  • Token模型處理文字時使用的片段單位。↗
  • Tokenizer／BPE分詞器及其中一種建立詞彙表的方法。↗
  • Context Window單次處理可容納的上下文範圍。↗
  • Temperature／Top-p部分模型控制生成隨機性或候選範圍的設定。↗
  • Knowledge Cutoff模型訓練資料的時間範圍線索。↗
  • Embedding把內容轉成可比較的向量表示。↗
  • RAG先檢索相關資料，再交給模型回答。↗
  • MoE模型內按輸入選用部分專家模組的架構。↗
  • Pre-training在大量資料上訓練基礎模型。↗
  • Fine-tuning以特定資料繼續訓練，讓模型適應任務。↗
  • LoRA以較少可訓練參數進行微調的方法。↗
  • Distillation讓學生模型學習教師模型行為的訓練方法。↗
  • Transformer許多語言模型採用的架構，用多層運算處理上下文。↗
  • Attention計算不同位置的資訊如何互相影響。↗
  • Inference使用已訓練的模型處理輸入、產生輸出。↗
  • Memory保存與取回資訊；要分清本輪 Context 和外部記憶。↗

提示詞與上下文

  • Prompt給模型的任務或指示。↗
  • System Prompt應用程式提供的系統層指示。↗
  • Context Engineering挑選與管理每次請求所需的資訊。↗
  • Compaction以摘要等方式整理過長的上下文。↗
  • Progressive Disclosure依任務需要逐步載入相關資訊。↗
  • Context模型這一輪實際收到的任務、前文、資料和工具結果。↗

Agent 與工具

  • Agent圍繞目標選擇行動並觀察結果的系統。↗
  • Agent Loop選擇、行動、觀察，再決定下一步。↗
  • Tool Calling請求應用程式執行工具並取得結果。↗
  • Harness協調模型、工具、權限與限制的框架。↗
  • Background Agent在背景環境依條件持續工作的代理人。↗
  • Computer Use透過畫面、滑鼠和鍵盤操作電腦的能力。↗
  • Skill可重複使用的工作指引與資源。↗
  • MCP連接 AI 應用、工具與資料的協定。↗
  • Human-in-the-Loop在需要判斷或授權時由人參與確認。↗
  • Multi-Agent由多個代理人分工並交接結果。↗
  • Workflow事先安排好的工作路徑，也可以包含條件分支。↗
  • Tool應用程式提供的可執行操作，例如讀取檔案或計算。↗
  • Schema約定工具請求要填哪些參數，以及參數的格式。↗

安全與查證

  • API／API Key程式連接服務的介面，以及用來驗證的憑證。↗
  • Usage服務回報的用量，可能分列輸入、輸出與其他項目。↗
  • Hallucination模型產生缺乏依據或與事實不符的內容。↗
  • Prompt Injection外部內容試圖影響或改變原本的指示。↗
  • Guardrail／Sandbox檢查措施與受限制的執行環境。↗
  • Evals用測試案例與完成條件檢查系統表現。↗
  • Trace記錄可觀察的工具請求、結果與錯誤，方便找出問題。↗

圖形與介面

  • Graphic以圖表、圖像或圖解呈現資訊。↗
  • Generative UI依任務或模型結果產生的互動介面。↗
